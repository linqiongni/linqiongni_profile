## 一、五条硬规则（任何产出都必须满足）

1. **事实依据原则**：不编造事实。案情、数据、金额能查就查，查不到就写"待核"或"未检索到权威来源"。
2. **法律依据原则**：法条必须可查、条号必须标版本。引用《公司法》默认指 **2023 修订、2024-07-01 施行** 版；《证券法》指 2019 修订版。旧条号（如九民纪要引用的 35 / 142 / 166）必须给出换算后的现行条号。
3. **不确定即标注**：口径不一致、数字有版本差异、检索不到权威来源的，一律在正文里就地标注，不静默处理。
4. **保密义务**：案件材料、客户信息、内部文件不外传、不写进示例、不上传外部服务。
5. **执业边界**：所有产出是学习/工作底稿，须经 Andy 复核后方可作为正式文件使用；重大权益判断（起诉、和解、对外承诺）由人决策。

## 二、本项目的固定产出结构

每一站 HTML 的骨架（改内容不要动骨架）：

```
剧情 → 术语卡（中英对照） → 大白话打比方 → 结构图（SVG） →
法务对话（可折叠） → 常见坑（details.peek） → 案例剖析（vs 对照） →
条款模板（details.tpl） → 延伸真实案例 → 自检清单 → 法源索引
```

## 三、写作风格（Andy 明确要求）

- **结论先行**，再给理由；不铺垫背景。
- **不谄媚**：不写"这是个好问题""当然可以""内容已上线"。
- **大白话优先**：每条法务术语必须配一句"老板/投资人听得懂的话"；必要时用对话体（老板问大白话 → 法务答大白话 → 翻译成条款）。
- 中文正文，代码/文件名/变量名用英文。
- 给出选项时说清"为什么"和"对用户的影响"，不是只讲实现。

## 四、技术约束

- 纯静态：无构建、无 CDN、无外部请求。`assets/style.css` + `assets/app.js` 是全站共用。
- 新增章节：复制 `ch*.html`，并在 `assets/app.js` 的 `STATIONS` 数组加一条（导航与上下篇自动生成）。
- 折叠块用原生 `<details>`：`details.peek`（详解）、`details.tpl`（模板）、`details.dlg`（法务对话）。
  顶部批量按钮 `data-fold="open|close"` + `data-fold-kind="peek|tpl|dlg"`（`+ data-fold-scope` 可限定范围），app.js 已通用支持，**新增 kind 无需改 JS**。
- 主题：浅色为默认（`html[data-theme]`），深色靠 CSS 变量；**颜色一律用 var()，禁止硬编码色值**。
- 部署副本在 `linqiongni_profile/public/financing-legal/`，改完源站执行 `npm run sync:financing`，不要只改 public 副本。
