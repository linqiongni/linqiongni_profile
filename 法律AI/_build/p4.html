8.2 逐周明细

阶段 S0 · 立项（W1–W2）

  • W1
    拉数据：法务工单全年统计

    从 OA / 邮箱 / 企微里导出过去 12 个月全部法务工单，按业务域分类计数，产出真实的工作量分布表（替换第 01 章的估算值）。

    交付：《法务工作量分布报告》——这是整个项目的地基，也是说服老板最有力的材料

  • W1
    组团队 + 申请测试环境

    项目组：法务总监（发起人）+ 法务专员 1–2 名（业务负责人、语料负责人）+ IT 1 名（部署运维）。申请一台测试服务器（建议 16 核 / 32–64GB 内存起步，有 GPU 更好）。

    交付：项目组名单与职责、测试环境到位

  • W2
    合规书面结论

    按第 07 章逐项形成书面判断：是否构成生成式 AI 服务提供、数据出境方案、个人信息处理合法性基础、License 核查结论（尤其 Dify）。

    交付：《法律 AI 项目合规意见》（留档，这是法务部的护身符）

  • W2
    立项报批

    一页纸立项：问题（工单数据）+ 方案（场景优先级）+ 投入（第 09 章预算）+ 回报（第 02 章成功标准）+ 风险（第 11 章）。

    交付：预算批复、六条红线规则签署确认

阶段 S1 · 试点（W3–W8）

  • W3
    部署 RAGFlow（Docker Compose）

    IT 按官方文档起服务，接本地 Ollama / vLLM 与 bge-m3。法务同步准备 P0 法规文本。

    交付：系统可访问，能上传文档并问答

  • W3–W4
    L1 内地法规入库（先做 P0 的 8 项）

    民法典（合同编/侵权编）、消法 + 实施条例、产品质量法、广告法、劳动合同法、GB 11887、GB/T 16552、GB 28480。每条带生效日期与来源 URL，按「条」分块。

    交付：L1 核心法规库可用；抽样 30 条检索验证通过

  • W4
    写第一批 prompt + 六条红线落地

    把第 02 章六条红线写进 system prompt：无引用拒答、禁止终局判断、强制免责尾注。输出格式用 JSON Schema 约束。

    交付：prompt v1 + 护栏规则文档

  • W5
    出黄金测试集 v1（50 题）

    法务部自己出题，覆盖 P0 场景的真实高频问题，每题标注标准答案 + 应命中的正确依据。这是未来所有回归测试的基准，不能外包、不能让 AI 出题。

    交付：Golden Set v1（50 题，含标准答案与预期引用）

  • W6
    内部小范围试用 + 首轮调优

    法务部 3–5 人先用，记录每一个答错 / 答得不好的案例，分类归因（检索没召回？分块错了？prompt 问题？模型问题？）。

    交付：问题清单 + 调优记录（这份归因表比任何文档都值钱）

  • W7
    接入企业微信 + 开放给 2 个试点区域

    选 2 个配合度高的区域做试点，门店店长通过企微提问。关键是入口要顺手——让店长另外登录一个网站，等于没人用。

    交付：企微机器人可用；试点区域培训完成

  • W8
    S1 验收 + 阶段汇报

    跑黄金集，出引用准确率报告；统计试点区域使用数据；向管理层汇报，争取 S2 资源。

    门槛：引用准确率 ≥90%，法务周活 ≥60%

阶段 S2 · 打透（W9–W16）

  • W9–W10
    写《租赁谈判底线清单》

    法务部闭门产出：10 类核心条款 × 每类的可接受区间 / 谈判目标 / 红线。这件事不需要任何技术，是纯法务资产，且即使项目中断也不亏。

    交付：《门店租赁谈判底线清单 v1》（密级：内部）

  • W10–W11
    50 份历史租约脱敏入库

    选 50 份有代表性的（不同业态、不同区域、不同年份）。脱敏：房东主体、租金金额、抽成比例。按条款切分，带元数据。

    交付：L3 租约库（脱敏）；脱敏规则文档

  • W12–W13
    Dify 搭建租约审查工作流

    流程：上传 PDF → 条款切分 → 逐条比对底线清单 → 风险分级（红/黄/绿）→ 生成修订建议 → 人工复核节点。复核节点必须是流程里的硬卡点，不能跳过。

    交付：租约审查工作流可用；产出模板三件套

  • W14
    20 份回测

    拿 20 份法务已审过的租约做回测：AI 找出的风险点 vs 法务当年人工标注的风险点，算召回率与误报率。

    交付：回测报告；门槛：召回率 ≥85%

  • W15
    权限矩阵落地 + 审计日志

    按 4.2 表配置角色与语料可见范围；开启全量查询审计；运维账号访问留痕。

    交付：权限配置文档 + 审计日志可查

  • W15–W16
    香港法例入库 + 双法域切换

    从 data.gov.hk 开放数据获取香港法例现行版，建香港法域语料库；prompt 支持按法域切换输出语种与依据。

    交付：双法域问答可用

  • W16
    S2 验收

    门槛：风险点召回率 ≥85%；单份租约审查耗时下降 40%

阶段 S3 · 扩张（W17–W24）

  • W17–W18
    商品与营销合规预检

    建禁用词库与强制标准映射，批量预检商品标题 / 详情页 / 直播脚本。

    交付：预检工具上线；抽检 100 条历史文案验证

  • W19–W20
    消费者投诉处置 + 劳动争议

    两个场景并行：处置话术与证据清单；劳动分析与金额试算。

    交付：两个场景上线；话术模板库

  • W21
    自动化回归评测流水线

    把黄金集 + Ragas/DeepEval 接进 CI：每次 prompt 改动、语料更新、模型升级都自动跑一遍，指标下跌就报警。这是系统不腐坏的保险丝。

    交付：评测流水线；指标看板

  • W22
    运营手册 + 责任人 + 培训

    写《法务 AI 系统运营手册》：语料更新流程、责任人、复核要求、红线。对全员做一次培训。

    交付：运营手册；培训完成；责任人任命

  • W23
    效果复盘 + 度量报告

    统计工时节省、采纳率、引用准确率、幻觉率，与第 02 章承诺值对比。

    交付：《首期效果复盘报告》

  • W24
    S3 验收 + 二期规划

    门槛：季度净节省 ≥200 工时；引用准确率 ≥95%；交付：二期预算提案（P2 场景 + CLM 集成）

排期上唯一不能让步的一点

W5 的黄金测试集必须在系统调优之前，而不是之后。很多团队先调系统、调到最后才想起「怎么证明它变好了」，结果只能凭感觉。先出题、后调优，才有客观基线。

09预算：三档方案

按集团规模给三档。建议从轻量档起步——先用现有资源证明价值，再追加投入。一次性上重资产，风险是「钱花了但没人用」。

方案 A · 轻量起步

首年约 ¥8–15 万

  • 复用现有服务器（16C / 32–64GB）
  • 全部开源自建，零 license 费用
  • 生成模型走云端合规 API（非涉密场景）
  • IT 兼职投入，法务自己整理语料
  • 覆盖：法规问答 + 单一场景

适合：先验证价值、预算未批

方案 B · 标准（推荐）

首年约 ¥45–70 万

  • GPU 服务器 ×1（48GB 显存级）约 ¥15–22 万
  • 应用与数据库服务器 约 ¥5 万
  • 本地模型部署与调优 约 ¥10–15 万
  • 语料整理（可外包部分）约 ¥8–12 万
  • 实施与培训 约 ¥5–8 万
  • 年度运维 约 ¥5–8 万

适合：200+ 门店规模，全本地私域，覆盖 5 个场景

方案 C · 规模化

首年约 ¥120–200 万

  • GPU 服务器 ×2 + 高可用架构
  • 双法域双区部署（内地 + 香港）
  • 与合同管理系统（CLM）/ OA 集成
  • 专职 AI 运营岗 ×1
  • 覆盖全部 8 个场景 + 定制开发

适合：集团级推广、多品牌共用

预算谈判的三个支点
  • 对标外部律师费：一份租约外部律师审查的市场价 vs 系统年化成本，分母是「每年 60–90 份」。这个对比最容易打动 CFO。
  • 对标风险成本：一次标签不合规的行政处罚 + 舆情损失，往往高于系统首年投入。把同行公开处罚案例放进立项材料（L4 语料本来就要收集）。
  • 不要承诺「减少法务编制」。承诺效率提升与风险控制，不承诺裁员——后者会让项目在内部失去配合，而且也不属实。

10评测与度量：让系统不腐坏

没有评测的 AI 系统，三个月后就会悄悄变差——语料更新了、prompt 改了、模型升了，没人知道效果怎么样了。评测体系是这个项目的保险丝。

10.1 黄金测试集（Golden Set）

怎么出题
  • 来源必须是真实问题：从过去一年的工单、企微咨询记录里挑，不是拍脑袋编。
  • 每题三部分：问题 + 标准答案要点 + 应命中的正确依据（法规第几条 / 制度第几章）。第三部分最关键——它让「引用对不对」变得可自动判定。
  • 覆盖分布：按第 01 章工作量分布配比，高频场景多出题。
  • 必须包含「陷阱题」：10% 的题目是知识库里没有答案的，用来测试系统会不会老实说「不知道」。系统敢不敢拒答，比它答对多少更重要。
  • 规模：v1 出 50 题（W5），S2 扩到 100 题，稳定后 150–200 题。
  • 禁止 AI 出题：让模型自己生成测试题，等于让它自己出考卷自己判分。

10.2 核心指标

指标目标值怎么测为什么是它
引用准确率≥95%抽取回答中的引用编号 → 与知识库原文比对是否存在且内容一致第一指标。引用错了，一切免谈
幻觉率≤2%Ragas faithfulness / DeepEval hallucination：逐句判断答案是否被检索上下文支持法务场景的致命指标，一次编法条就能毁掉信任
拒答正确率≥90%陷阱题上是否输出「未检索到依据 / 转人工」衡量系统是否「知道自己的边界」
检索召回率≥90%正确依据是否出现在 Top-5 检索结果中用于区分「检索没找到」和「找到了但生成错了」
采纳率≥60%AI 产出被法务采纳（未大幅修改）的比例业务价值指标，比准确率更真实
首答可用率≥70%门店提问后无需转人工即可解决的比例衡量一线场景是否真跑通
工时节省≥200h/季场景前后耗时对比 × 使用频次汇报用，也是立项承诺的兑现证据
周活人数≥80%系统后台统计没人用说明场景选错了，其他指标再好也没意义

10.3 回归评测流水线（W21 建）

  1. 触发条件：语料批量更新、prompt 修改、模型版本升级、RAG 参数调整——任一发生即触发。
  2. 自动执行：跑完整黄金集 → 计算全部指标 → 与基线对比。
  3. 熔断规则：引用准确率或幻觉率跌破阈值 → 自动阻断上线 + 通知法务负责人。
  4. 人工抽检：每月法务人工抽 20 条真实问答，检查「自动化指标看不出来的问题」（比如语气、口径与公司文化不符）。
  5. 回流机制：人工修正过的答案 → 进入 L4 语料 → 下次遇到同类问题答对。这是系统越用越聪明的唯一路径。
