# 决策日志

**这份文件的价值在于「被否决的路径」。** 代码能告诉你最后选了什么，但不能告诉你还有别的路、以及为什么那条没走。换个人接手，省的就是这一段。

只记**不可逆的、花了时间的、以后还会重提的**事。小改小动不进这里。目标总量 ≤ 20 条（当前 7 条）。

格式：背景 → 选项 → 选中 → 代价 → 保留意见。

---

## 01 · 全站暗黑配色定稿为深海军蓝（2026-09-22）

**背景**：改暗色时只改了主站（苹果灰 `#1C1C1E` 系），十几个 iframe 子站没跟着改，深浅不一致；且各站各写一套变量，改一次要动十几处。

**选项**
- A. 继续用苹果灰，只主站和子站分别微调 —— 否决：改一次动十几处，必然漂移
- B. 主站统一下发 CSS 变量，子站覆盖 —— 否决：iframe 是独立 HTML 文档，变量传不过去
- C. 主站与子站共用一套色值常量，写进各自的 `assets/style.css` —— **选中**

**色值**：主底 `#091A2E`、卡片 `#0C1B2B`、描边 `#1B2E45`、页脚 `#06101C`、
文字 `#F4EFE4` / 次要 `#93A6BC`、金色统一 `#C9A86A`。body 固定渐变 + 右上径向蓝光。

**代价**
- 子站改配色仍要手动同步，没有构建期校验，也没人提醒你漏了哪个
- 新增子站若忘写暗色块，加载瞬间会白闪一下

**保留意见**
- 这套色值在 2026-09-22 当天改了三次（22:00 定稿后又迭代到深夜），说明**还没收敛**。
  真正的稳定版应该在子站数量不再增长之后才算数，现在写死为时尚早。
- 金色 `#C9A86A` 与旧的 `#967a48` 在 `AboutTab` 里仍靠 `!important` 覆盖，说明「统一」还没做完。

## 02 · 深度详解从「跳到页尾」改为「原地展开」（2026-09-18）

**背景**：融资法务站要把关键概念展开详解。第一版（`.deep`）把详解折叠面板统一放页面下方，正文关键字上放一个 `详解` 锚点，点击后 `scrollIntoView` 跳过去。

**Andy 的原话**：「不要跳到下面去」。

**选项**
- A. 折叠面板统一放页尾 + 锚点跳转 —— 否决：看完要往回翻找原文，阅读链路是断的
- B. 每一行详解都就地插在对应段落之后 —— **选中**

**选中**：`.peek` 原地展开（`<details class="peek">`，直接插在对应段落后）；
配套 `.tpl` 可折叠协议模板、`.tplbar` 控件条（只切换展开状态，**不滚动**）。

**代价**
- 页面变长，一屏看到的东西少了
- 同一段落后有多个详解时，视觉上会显得碎

**保留意见**
- 「不滚动」这条约束是对的，但它意味着长文阅读体验天然不如折叠到页尾。
  如果以后某站内容密度高到需要连续展开，得再想别的办法，不能硬套这个模式。

## 05 · 英语站字体自定三层变量，不引 Google Fonts（2026-09-19）

**Andy 要求**：「典雅高级低调奢华、别浮夸」。

**选项**
- A. 引 Google Fonts（如 Noto Serif） —— 否决：国内不稳定，且 iframe 里外部资源会阻塞加载
- B. 用系统字体栈，分三层变量 —— **选中**

**选中**：`:root` 里定义 `--en-serif`（正文）/ `--en-display`（标题）/ `--en-ital`（斜体）三层，
英文 serif 栈为 Iowan Old Style → Charter → Baskerville → Palatino → Georgia，中文另走 `--cjk-serif`。
正文 18.5px/1.95，标题 28px/weight 500。

**代价**
- 不同操作系统渲染差异明显（macOS 走 Iowan，Windows 会落到 Georgia，字形差距大）
- 换来的是零外部请求、国内可用

**保留意见**
- 「别浮夸」和 Georgia 这种常见 Windows 默认衬线其实是矛盾的。
  如果哪天发现 Windows 上观感掉档，加一层 `Hoefler Text` / `Constantia` 兜底即可，不必推翻。

## 06 · iframe 主题同步用 postMessage，小时级版本号穿透缓存（2026-09-18 / 09-19）

**背景**：主站切深浅色，iframe 里的内容不变色（iframe 是独立文档，拿不到父站的 CSS 变量）。

**选项**
- A. 让子站自己监听系统 `prefers-color-scheme` —— 否决：主站是用户手动切，系统设置不代表用户选择
- B. 主站 `postMessage` 下发主题，子站监听 —— **选中**

**实现**：React 侧统一走公共组件 `ThemeIframe`；静态页引 `/theme-toggle.js` 并监听
`{type:'theme', mode:'dark'|'light'}`。**必须在 iframe 的 onLoad 之后发**，早发会丢。

**追加决策（2026-09-19）**：iframe 的 src 挂 `IFRAME_V` 版本号，粒度是**日期+小时**。
原因同 `#07`——只挂日期时，同一天内改样式用户看不到。英语站是唯一例外（它把 `?v=` 透传给 `scenes.js`，防「旧 HTML + 新数据」白屏）。

**代价**
- 版本号要手工维护，忘了加就是「改了看不到」
- 英语站的 `?v=` 必须一路透传，漏一处就白屏

**保留意见**
- 「日期+小时」粒度是靠人工守的。以后子站多了，应该改成构建期自动生成，或者干脆走 hash 文件名。现在这套能跑，但会在某个深夜骗过一次人。
