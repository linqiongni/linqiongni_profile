# 开场白 — 复制一段话丢给 WorkBuddy 就行

> 什么时候用：每次开工、换设备、隔几天重新接手、开一个新会话。
> 用法：**整段复制下面那句话，把 `<…>` 换成实际情况，粘进新会话。**
> 不用背格式、不用按条目念——里面该说的都说了，AI 读完会自己去 `process/` 里找细节。

---

## 一、日常开工（这台电脑上接着干）—— 复制这段

```
这是我的 git 项目 https://github.com/linqiongni/linqiongni_profile，目录在 ~/Downloads/linqiongni_profile，
我接着开发 linqiongni_profile（个人主页 + 法务作品集，线上 https://linqiongni.top）。

开工你先按顺序读三份：process/CONTRACT.md（行为规则：收工要做什么、git 怎么走、哪些不能碰）、
process/README.md（唯一入口，写着现在还挂着什么没解决、上一个人干到哪）、
process/03-问题台账/OPEN.md（开工先看有没有你该认领的）。
要动 src/ 或发布相关，先补读 process/01-项目现状/workflows.md，八条红线，本地别跑 npm run build。

git 这块你不用管 pull/push，自动同步的 hook 已经装好了：进目录自动拉最新，提交后自动 rebase 再推上去。
你只要 git commit 就行。别手写 git push（会和 hook 打架），也别把 pull 挪到 pre-commit
（改动还挂在 index 上时 rebase 会把正在提交的这批搅没，实测过）。
推 main 等于把线上发一遍，做了一半的东西只推 wip/YYYYMMDD 分支。push 不通去 process/MIGRATION.md 第三节查。

收工五件事：写当日日志（文件已存在就追加，禁止覆盖）→ 更新 process/README.md 的「今日索引」→
有真问题提台账、有新的决定进决策日志 → git commit（hook 会自己推）→
**动了 src/ 或任何子站的话，最后 curl 一下线上，确认改动真的生效了。**
push 成功不等于线上生效——GH Pages 有 10 分钟缓存，现成命令在 process/01-项目现状/workflows.md 第三节。

现在，这次接手你打算接着做什么？以及你今天收工前会做哪几件事？
```

> 最后那句「**你今天收工前会做哪几件事**」别删。实测过：删掉它 AI 照样会把那些步骤做掉，
> 区别只在它会不会**主动汇报**。**那句买的是你的知情权，不是它的自觉。**

## 二、换设备 / 新 clone（前面还要在终端跑两行）

开场白之前，先在这台新机器上跑：

```bash
git clone https://github.com/linqiongni/linqiongni_profile.git
cd linqiongni_profile
bash scripts/setup-device.sh          # 装自动同步并当场自检六项，约 10 秒
```

然后把上面那段开场白的开头改成两句话，接着往下说：

```
我换了一台设备，刚把仓库 clone 下来，自动同步也装好了。
这是我的项目 https://github.com/linqiongni/linqiongni_profile，我接着开发 linqiongni_profile（个人主页 + 法务作品集，线上 https://linqiongni.top）。
<下面接着「开工你先按顺序读三份……」那一段>
```

- **自动同步的 hook 不进 git**，clone 必然不带，所以换设备这一步每条机器都得跑一次，跑完永久生效。
- `scripts/setup-device.sh` 必须先被 push 过，新机器才 clone 得到。2026-09-27 实测踩过：
  新设备上报 `No such file or directory`，因为那个文件只是本地新建、还没推。

## 三、另一台电脑已经 clone 过（老设备首次同步同一套机制）

**不能直接让它 `git pull` 就完事。** pull 只搬代码，`scripts/install-git-hooks.sh` 装出来的 hook 住在
`.git/hooks/` 里、**不进 git**，拉多少次那台机器都不会自动 pull/push。要动得有三下。

顺序（在那台电脑上，终端或让那台电脑的 WorkBuddy 跑都行）：

```bash
git status          # 先看有没有没提交的改动，有的话先记一笔/commit
git pull --rebase   # 把 scripts/ 和 process/ 拉到最新
bash scripts/setup-device.sh
```

> 那台电脑要是今天也在动同一个仓库，两边改了同一个文件就会冲突。**冲突不会丢改动**，
> 照 `CONTRACT.md` 第四节那句处理：改完冲突标记 → `git add` → `git rebase --continue`。
> 别在没看清 `git stash show -p 'stash@{0}'` 内容之前 drop 任何东西。

同步完之后，把这段丢给那台电脑上的 WorkBuddy——**它并不知道这些机制存在**，你不说它就是不知道：

```
我在这台机器上把 linqiongni_profile 同步到了最新，顺便给这台机器装上了自动同步。按顺序做三件事：

1. git pull --rebase       把 scripts/ 和 process/ 拉到最新
2. bash scripts/setup-device.sh   装自动同步并自检六项（hook 不进 git，pull 拉不到，只能在这台机器装一次）
3. 读 process/开场白.md 和 process/CONTRACT.md   从现在起，这个仓库该怎么做人做事，以那两份为准

这套东西在哪，我给你交代清楚：
- 自动同步藏在 .git/hooks/ 里，不是你看得见的脚本，但一直生效：进目录/切分支自动拉最新，提交后自动 rebase 再推。
  所以收工你只要 git commit，别手写 git push（会和 hook 打架）；也别把 pull 挪到 pre-commit（改动挂在 index 上会被 rebase 搅没）。
- 推 main 等于把线上 https://linqiongni.top 发一遍。做了一半的东西只推 wip/YYYYMMDD 分支。
- push 不通去 process/MIGRATION.md 第三节查，四种根因，别自己瞎试半小时。
- 行为契约是 process/CONTRACT.md，过程档案在 process/，唯一入口是 process/README.md。
  开工读这几份；收工写当日日志 + 更新今日索引 + 提台账/决策 + git commit +
  动过会发布的东西就 curl 验一下线上有没有真的生效。

最后，这次你打算接着做什么，以及你今天收工前会做哪几件事？
```

## 四、这份文件的其它说明

- 为什么单开一个文件：开场白散在 `MIGRATION.md` 第七节时是"当时版"，写完就过期；
  分开存能单篇维护，也不必回头改迁移文档。`MIGRATION.md` 里那段保留只为向后兼容，别再改它。
- 六条未决目前没写死在开场白里了，**让 AI 自己去 `OPEN.md` 看**——写死就会过期，
  而且过期清单比没有清单更危险：它会让接手的人照着过期信息执行。
- 认领判据（防它乱抢活）：署名 Andy、写着「等他拍板」、需要他本人操作或外部权限的，不认领；其余默认归它。
