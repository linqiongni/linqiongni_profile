## 追加（当天下午，第六件事）· 半途打包机制

Andy 问：「开发一半的功能，怎么让它把当前状态、思路都打包上去 git，换个电脑能继续干。」

**先查出一个会伤到线上的事实**：`.github/workflows/deploy.yml` 是 `on: push: branches: [main]`。**半成品推 main 会触发构建，并发到 linqiongni.top。** 所以「怎么打包」的答案里，有一条是「只能推 wip 分支」。这条以前没人提过，踩上去就是拿线上用户试错。

配套两样新东西：`process/HANDOFF.md`（断点卡，七节，含与 OPEN 台账 / 每日日志的边界表）和 `scripts/wip-snapshot.py`（现场快照：分支 / HEAD / 未提交改动 / 今天动过哪些文件）。

**第四次实测（新 AI 走打包流程）的评语很值钱**：

- **「卡的不是流程是纪律。」** 规则写得再清楚，「先把前三节填满」这一步没有任何校验，跳过也照样能跑完后面四行。
- **「机制假定上一个人一定会更新文档，而这恰恰是最容易松的那一环。」**
- 它自己发现了一个文档里没人写的东西：本地两条 stash（`stash@{0}` 含 2026-09-17 的日志、`stash@{1} wip-MEMORY`）和一条从未 push 的分支 `save-visual-f276c11`——**换机器就永久消失**，其中那份日志可能还是唯一的。已开台账 **#20** 等 Andy 定。

据此修三处：① 脚本加前置校验——前三节还是空占位符就**拒绝生成快照**（已两种情形实测：空卡拒、已填放行）；② `HANDOFF.md` 前五节填成真实状态，消掉「卡里写着没在做事、磁盘上一堆未提交改动」的不一致；③ 修正 `CONTRACT.md` 第七节「四行」与实际对不上，补「快照会过期、push 前重跑」。

如果重来：**凡是靠人自觉的环节，都要配一道机器校验。** 前四轮我们一直在写「应该怎么做」，这一轮才第一次写「不这么做会怎样」——后者才拦得住。

## 追加（当天下午，第七件事）· 打包压成一条命令，并实跑一次

实跑抓到脚本自己的两个缺陷，都花了排查时间：

1. **用 stdout 判 git 成败是错的。** 中文 locale 下 `git checkout -b` 成功也往 stderr 打 `create mode 100644 …`，`git commit` 成功时 stdout 是空串。结果把成功报成「建分支失败」，还把 `create mode …` 当成提交信息打印出来。**调 git 一律看返回码。**
2. **多块文本拼接用 `+` 会粘连。** 两份 `todo()` 返回值相加，末行变成 `- \`scripts/wip-pack.py\`_（无）_`。

如果重来：**先写一键脚本再写文档。** 这轮之前所有「打包指南」写的都是给人看的操作序列，只有真正敲一遍才发现漏的和错的，全在脚本那一层。
