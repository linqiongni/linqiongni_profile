# 2026-10-08 日志

## 主任务：新设备（Win）接入收尾 —— 本机 git 写不进远程跟踪引用，绕过并校准历史

**背景**：上一轮已在本机装好 MinGit、浅克隆、自动同步 hook（6/6 自检）、凭据转 wincred、origin=GitHub（主源/部署）/ gitee（私镜像）双远端。本轮目标是把工作树对齐到线上并收工（写日志 / 更新索引 / 提交 / 双推 / 验线上）。

**卡点（本环境真 bug，非偶发）**：这台机器 `git update-ref refs/remotes/origin/main <hash>` 返回 `rc=0` 却一个文件都不落盘；`refs/heads/*` 写入正常，唯独 `refs/remotes/*`（远程跟踪引用）整体失效。`git fetch` 打印 `[new branch] origin/main` 也不持久。后果：自动同步 hook 依赖的 `git pull --rebase` / `@{u}` 在这台上跑不起来——之前 `@{u}` 一直 `gone`。

**绕过方案（已写进本机 hook）**：`git fetch` 能可靠写 `FETCH_HEAD`，所以用 `FETCH_HEAD` 当"远程 tip 真相源"，pull 改成 `git fetch <remote> <branch> && git rebase FETCH_HEAD`，完全不碰坏掉的 `refs/remotes`。上游也不靠 `@{u}` 解析，改从 `branch.<b>.remote` 配置取（拿不到默认 origin）。

**历史校准（关键发现，推翻上一轮"ahead 1 / behind 31"的误判）**：本地 `main`（`0566052`，单根提交）与 GitHub `d2b2db` **无共同祖先**（`git merge-base` 返回 rc=1）。`d2b2db` 本地已有 351 个提交的完整历史，历史里明写 `f85b22d chore: squash history to a single root commit` —— Andy 把旧历史压成单根后又建了 350+ 提交；而 `0566052` 声称的"修复滚动容器"在 `d2b2db` 里早有了（还更多：`af5909f fix(humanities): 修移动端滚动`、`a204748 fix(layout): ...`）。两棵树 2752 vs 2751 个路径，几乎完全相同。结论：本地 `0566052` 是过时孤立根，对线上无任何独特贡献；rebase 不可能（无共同祖先）、merge 不相关历史是灾难。

**处置（防丢优先）**：
1. `git branch backup/device-main-0566052 0566052` —— 整条本地线存进本地备份分支，随时可回。
2. 唯一"只在 0566052 有、d2b2db 没有"的文件是 `process/04-每日日志/2026-10-04.md`（两棵树差这一个）。已另存一份到仓库外 `D:/lins/_rescue_2026-10-04.md`，并保留在 backup 分支；d2b2db 没有它，是否要回 main 待 Andy 定。
3. `git reset --hard d2b2db` —— 采用 GitHub 当前真源。reset 后 `process/` 子目录一度没被写出来（本机 git 对中文嵌套路径 checkout 偶发静默失败，只影响 process/ 子目录，src/public 完好），用 `git checkout -f HEAD -- process/` 强制从索引恢复，已确认 CONTRACT / MIGRATION / OPEN 等全在、`git status` 干净。

**本机 hook 修复（`.git/hooks/`，不入库）**：
- `T12=(timeout 12)` bash 数组写法改成 POSIX 的 `T12="timeout 12"`（否则被 `sh`/dash 解释直接 `syntax error` 崩，远端探测全废）；
- pull 改用上面说的 `FETCH_HEAD` 方案，不再依赖 `@{u}` / `refs/remotes`。
