## 玻璃化（embedded-glassify）四轮返工：保护口径的最终结论

Andy 连续三次报「又有蓝底」，一条线把口径推到底：

| 轮次 | 做法 | 结果 |
|---|---|---|
| ① `fe3fa35` | 纯色分支加「宽≥200 且 高≥120」尺寸保护（为救胶囊金底） | 61px 高的**通栏顶栏**被当小控件跳过 → 子菜单栏蓝底复发 |
| ② `fa1e174` | 改「宽≥400 或 高≥120」 | 顶栏好了，**侧栏条目/选中项/搜索框/表头**又被保留成蓝 |
| ③ `fbef262` | **尺寸保护彻底废除**，除 class 含 `tab` 外一律清透明 | 回到用户认可的全透明基准，通过 |
| ④ `657c0e6` | 豁免扩到 `nav.tabs` 内的按钮（涉外合同指南页胶囊类名不含 tab） | 该页选中态深金渐变恢复 |

**这条线的本质结论**：按尺寸豁免这条路不通——**豁免线划到哪，哪批元素就蓝回来**。
豁免白名单唯一的准入理由是**交互态死锁**（底色随 class 切换、被 inline `!important` 永久压制后无法自愈），
不是「元素小」「看起来像控件」。已固化进 `skills/fixed-bg-fish-bug/`。

配套修的两处：glassify 加 **class/style 属性 MutationObserver**（防抖 120ms 补扫，解决 `display:none`
面板加载时 0 尺寸被跳过、切 tab 后深底裸露）；三处页面 `window.scrollTo({top:0})` 改为滚到 tabs 容器上缘。

**教训（写进技能了）**：动玻璃化必须跑十项回归清单，不许只验用户报的那一个元素；本地探针前先验
iframe 里的脚本版本（`hasNew`），否则浏览器缓存给你假读数。

## 把技能层拉进 git（回答「换台电脑它会不会懂」）

问出来的真问题是：**技能全在本机 `~/.workbuddy/skills/`，而 `.workbuddy/` 被 gitignore**——
clone 下来的仓库里一条技能都没有，新机器上的 AI 等于从头猜。同理，昨晚的日志和 `MEMORY.md` 更新也写进了
`.workbuddy/`，属于「写了但没写」。

处理：仓库建 **`skills/`** 作为唯一真源，六份本仓库专属技能搬进去
（`fixed-bg-fish-bug` / `inline-reading-view` / `profile-site-sync-publish` / `sub-site-style-align` /
`weekly-plan-publish` / `legal-domain-site-tab`）；本机目录换成指向它们的**软链**（改仓库那份，本机同步生效）。
`scripts/setup-device.sh` 新增「接管技能」步骤并纳入自检——**新设备还是一条命令**，技能随 clone 自动装上。

**教训（复用 09-27 那条）**：凡是「装在机器上、不进 git」的东西（hook、技能、用户级记忆），
都必须配一条随仓库走的自动接管命令，否则换设备时永远会漏一层，而且不会报错、只会静默失效。

## ⚖️ 小律的补充（风险与保留意见）

- 软链接管有个**前提假设**：`~/.workbuddy/skills/<name>` 里如果已经存在**实体目录**（不是软链），
  脚本会拒绝覆盖并提示先手动合并——这是故意的，避免直接删掉本机独有内容。换设备第一次跑若报红字，按提示处理。
- 仍未 git 化的还有 `~/.workbuddy/` 下的 `MEMORY.md` / `SOUL.md` / `IDENTITY.md` / `USER.md` 四件套——
  它们属于跨项目身份层，是否入 git 由 Andy 定（详见 `MIGRATION.md` 零节）。**缺口还在，只是从「六份技能」缩小到「四份身份文件」。**
- 本次只对**本仓库专属**的六份技能做了托管；`domain-knowledge-static-site`、`project-archive-kit` 等通用技能
  留在用户级是对的（多个项目共用，进任一仓库都不合适）。
