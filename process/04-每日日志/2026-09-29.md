## 玻璃化（embedded-glassify）四轮返工：保护口径的最终结论

Andy 连续三次报「又有蓝底」，一条线把口径推到底：

| 轮次 | 做法 | 结果 |
|---|---|---|
| ① `fe3fa35` | 纯色分支加「宽≥200 且 高≥120」尺寸保护（为救胶囊金底） | 61px 高的**通栏顶栏**被当小控件跳过 → 子菜单栏蓝底复发 |
| ② `fa1e174` | 改「宽≥400 或 高≥120」 | 顶栏好了，**侧栏条目/选中项/搜索框/表头**又被保留成蓝 |
| ③ `fbef262` | **尺寸保护彻底废除**，除 class 含 `tab` 外一律清透明 | 回到用户认可的全透明基准，通过 |
| ④ `657c0e6` | 豁免扩到 `nav.tabs` 内的按钮（涉外合同指南页胶囊类名不含 tab） | 该页选中态深金渐变恢复 |

**这条线的本质结论**：按尺寸豁免这条路不通——**豁免线划到哪，哪批元素就蓝回来**。
豁免白名单唯一的准入理由是**交互态死锁**（底色随 class 切换、被 inline `!important` 永久压制后无法自愈），
不是「元素小」「看起来像控件」。已固化进 `skills/fixed-bg-fish-bug/`。

配套修的两处：glassify 加 **class/style 属性 MutationObserver**（防抖 120ms 补扫，解决 `display:none`
面板加载时 0 尺寸被跳过、切 tab 后深底裸露）；三处页面 `window.scrollTo({top:0})` 改为滚到 tabs 容器上缘。

**教训（写进技能了）**：动玻璃化必须跑十项回归清单，不许只验用户报的那一个元素；本地探针前先验
iframe 里的脚本版本（`hasNew`），否则浏览器缓存给你假读数。
