## 追加（当晚 · ENGLISH 站配音改为离线预生成）

- **起因**：Andy 反馈 ENGLISH 站「播放很卡、很生硬」。定位：整篇连读被代码强制退回**系统语音**
  （`run()` → `synthPlayAll()`，注释写明 Kokoro 手机逐句 WASM 推理会卡死），且系统语音把所有句子
  **拼成一整段一次念完**，句高亮靠 `字数×60ms` 估算 → 既生硬、高亮还会漂，播中跳句是假的。
- **解法（照兰香如故）**：新增 `scripts/gen_english_audio.py` —— 逐句 edge-tts
  （`en-US-AriaNeural` @ -4%，与兰香同音色锁）→ 句间插 220ms 静音 → ffmpeg concat 成每篇一个 MP3
  → 算句级偏移 → 写 `身边的英语/audio/index.js`。播放器改为**播文件**：
  `audPlay(i, oneShot)` + `timeupdate` 反查当前句（真正的 seek，上一句/下一句/进度条不再假），
  语速走 `playbackRate`（不从头重播）。无配音或偏移条数与句数不符时自动回落旧链路。
- **规模**：28 篇 / 820 句 / 约 69 分钟音频 / 25MB（缓存 `.tts_cache/` 已 gitignore）。
- **踩的三个坑**：①极短句（7 字节）合成的 MP3 小于 1000 字节，被我的成功判据误判为失败 → 阈值改 400；
  ②并发偶发限流 → 加「失败串行补做」；③**英文段落里混中文**（s28 第 23 句整句就是「团圆.」）
  edge-tts 直接 `NoAudioReceived` → 无拉丁字母的句子用静音占位，其余照常合成（曾误把两句夹中文的长英文整句静音，已纠正）。
- **同步纪律**：`public/english/index.html` 是带 Kokoro 的新版（比源目录多近 200 行），
  改前先 `cp` 回写源目录，否则下次 `sync:english` 会把改造冲掉（MEMORY 里记过的老坑，这次提前避开了）。

## 追加 2（深夜 · 「点了播放没声音」排查与加载体验修复）

- **现象**：Andy 在线上点播放，按钮变「暂停播放」但无声。
- **排查**：本地 CDP 真实时间实测——本地秒播（8s 播 7.96s）；线上也能播但**启动取决于下载**：
  到 GitHub Pages 的链路波动大（实测 200KB/17s），整篇 1.2MB 弱网要几十秒甚至更久。
  旧代码点播放立刻把按钮切成「暂停播放」、无任何加载提示、缓慢下载不触发 error 也不回落
  → 长时间无声假死。**不是播放 bug，是加载体验缺陷。**
- **修复**（`身边的英语/index.html` + `src/components/ThemeIframe.tsx` + `scripts/gen_english_audio.py`）：
  1. **进篇目即预加载**（`audPreload`：go() 与首屏各调一次），点播放时多半已缓冲好；
  2. **加载中反馈**：`readyState<2` 时按钮显示「◌ 配音加载中…」+ toast，不再假装在播；
  3. **15s 超时回落系统语音**（canplay 回调 + 打断令牌 `audTok`，暂停/切篇作废等待），
     缓冲就绪后再 play（异步回调里 play，配合 iframe `allow="autoplay"` 保险）；
  4. `audio/index.js` 加缓存版本号 AV，**生成器自动 bump**（`bump_av()`），防老访客拿旧偏移表配新 MP3。
- **回归**：本地 CDP 复测通过（8s 播 7.96s、整篇缓冲、无错误）。
- **又抓到一个「以为修了其实没修」**：昨晚 commit 里 `.gitignore` 全局 `.tts_cache/` 和
  `sync:english --exclude .tts_cache` 都没真正落盘，今晚 rsync 又把缓存带进 public（已被 gitignore
  挡住没进 git）。已修正并复核。老教训再次应验：**多处 Edit 报成功≠落盘，改完必须 grep 复核。**

- **上线**：commit `a83e1e2`，线上已验到 `audPreload` 与新 AV 版本号。
