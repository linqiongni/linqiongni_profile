# CONTRACT.md — 行为契约（写给接手本仓库的 AI）

> 这份文件管的是「**你怎么做事**」，不是「项目是什么」。
> - 项目是什么、现在挂了什么没解决 → 看 `README.md`
> - 换机器 / 换账号怎么用 → 看 `MIGRATION.md`
> - 同一件事做完了 → 看 `03-问题台账/SOLVED.md`
>
> **你（AI）为什么读到这里**：`AGENTS.md` 把你送到这里。你接手了这个仓库，下面这些是约定，不是建议。

---

## 零、一句话

这个仓库有个 `process/` 档案库，记着这个项目**做出来的每一步和为什么**。
你每干一天活，就往里面加一天。**不做这件事，档案库三个月就腐烂成流水账，换人接手就只能靠猜。**

---

## 一、开工清单（每次会话开始，30 秒内）

1. **读 `README.md`** —— 入口，它告诉你现在挂了什么没解决、哪些决定不要推翻。
2. **读 `03-问题台账/OPEN.md`** —— 开工前先看有没有轮到你认领的条目。**看到 `Andy` 署名的条目，是等你点头，别自己动。**
3. **看一眼「今日索引」的最新一行** —— 确认上一班的人干到哪了，别重复劳动。
4. **要动 `src/` 或发布相关文件 → 先读 `01-项目现状/workflows.md`**。八条红线在动手前必读（本地禁 `npm run build`、只改中文源目录、改完 grep 核对……）。**只读前三步就改代码，等于对红线一无所知。**

> 如果日期是新的（没有今天这条）→ 你就是这一天第一个开工的，收工那节对你的权重最高。

## 二、收工五件事（做完才能说「做完了」）

按顺序来，除非某条确实无事可记：

| # | 动作 | 什么时候做 |
|---|---|---|
| 1 | **写 `04-每日日志/{今天}.md`** —— 照 `_templates/每日日志.md` 的格式。**文件已存在就在末尾追加，禁止覆盖** | 只要今天动过这个仓库的文件 |
| 2 | **更新 `README.md` 的「今日索引」** —— 加一行，别删表头 | 只要新增或改了档案库里的文件 |
| 3 | **提台账** —— 新卡住的开 OPEN 条目（写全四要素）；解决了的挪进 SOLVED，编号连着来 | 有真问题 |
| 4 | **新决定进 `02-决策日志/`** —— 只记不可逆的 | 你推翻或重定了某个做法 |
| 5 | **`git commit` + `git push`** —— 档案库和代码一起走 | 见第四节 |

**只有第 5 步可以跳过**：网络不通、凭据没配。**其余四步跳过一次，档案库就少一天。**

## 三、写日志的格式（照抄，别自由发挥）

**五段式**，缺哪段写「无」，别删标题：

```
# 2026-09-28 · 周一
> 一句话总结今天。
## 做了什么        3-5 条，每条一行，别写成段落
## 问题            新开 #20、解决 #14（引编号）
## 今日决策         一行；有线就进 02-决策日志
## ⚖️ 小律的补充     风险 / 保留意见 / 如果重来会怎么做（不许空）
## 有意思的         非显然的发现（没有就写「无」）
```

- **当天已有日志时追加，不覆盖。** 在文件末尾加一段 `## 追加（当天下午）`，把上面的五段重复一遍。**覆盖等于销毁当天全部记录**——2026-09-27 那天的日志就被分了三个时段追加，就是因为同一天多件事。
- **编号规则**：问题用全局递增的 `#20`、`#21`（跨文件唯一），当前已用到 #19（见 `OPEN.md` / `SOLVED.md` 顶部）。分配前先查重。
- **OPEN 条目必须写全四件事**：现象 / 卡在哪 / 谁该动 / **下次第一步做什么**。少了最后一条，三个月后就是一堆没人认领的待办。
- **日期不凭记忆写**。复盘、日志里的日期一律 `git log --format="%h %ad %s" --date=short` 核对。本仓库已经栽过一次：凭记忆把 09-24 写成 09-23。
- **改完别信编辑工具的回执**。`Edit` 报「成功」没落盘过三次，写完必须 `grep` 核对关键内容。同一个病根：信记忆、信回执、不验结果。

## 四、git 同步规则

- **档案库和代码一起 commit**，不分开推。分开推的后果是换机器时档案库落后几个版本。
- **push 之前先 `git pull --rebase`**（换机器后的第一次更重要）。`workflows.md` 红线 8 与本节是同一条，以本句为准。**不要只看「直接 push」的说法**——并发会话会回退已提交的编辑，跳这一步的代价见 `#18`。
- **push 不通先排查再求助**，顺序：`HTTP/1.1` → `userAgent` → 代理 → 网络。完整排障在 `MIGRATION.md` 第三节，别自己瞎试半小时。**四种根因里有一种是本地代理挂了**，判定命令写在那里。
- **`.gitignore` 只排构建产物**。往里面加东西之前想清楚：这东西换台机器还会需要吗？
- **凭据、token 一律不进仓库**，只记「在哪儿」。

## 五、禁止清单

1. **不要往 `.workbuddy/memory/` 写日志。** 该目录已被 `.gitignore` 排除，写进去等于没写，而且会和 `04-每日日志/` 分叉成两份。日志只进 `04-每日日志/`。
2. **不要在别处再造一份索引。** README 是唯一入口，单向引用。多个索引 = 必然腐烂。
3. **不要把结论写进行程。** `01-项目现状/` 只记此刻是什么样，会变的结论往上提到 README / 决策日志，过程留在日志。
4. **不要推翻没看过的决定。** 改配色、折叠交互、字体、动效前必读 `02-决策日志/`。`DECISIONS.md` 里明写「改色前先读」的就是这种。
5. **不要把案件材料、客户合同塞进来。** 保密边界见 `AGENTS.md`，这是这个仓库的私域范围。
6. **不要写「以后可能会用到」的文件。** 档案库死于无差别收集。

## 六、档案库腐烂自检（每周一次，周复盘时）

四项全过才算健康：

| 检查项 | 不健康长什么样 | 修法 |
|---|---|---|
| 今日索引有今天这行 | 索引最新一行是上上周 | 补写当日日志 |
| OPEN/SOLVED 编号连续 | 中间断号、或同一个问题两个号 | 合并或重编号 |
| 决策 ≤ 20 条 | 半年两百条 | 合并同类，只留还会重讨论的 |
| 有本周复盘文件 | 连续两周没复盘 | 写 `W##.md` |

## 七、这份契约怎么改

- 有你不认同的规则：**先照做，再提意见**。口头提，别偷偷不执行。
- 连续三次想改同一条 → 写进 `05-想法池/ideas.md`，等 Andy 点头再改本文件。
- **改完在文件末尾「版本记录」加一行**，写清改了什么、为什么。契约没有版本记录就等于没有约束。
