# 购物好官 · 构思初稿

> 日期：2026-09-16 ｜ 状态：待打磨（和用户一起定稿）

## 一、研究结论：市场空白在哪

- **真实需求已验证**：「自助服装店 / 社恐购物」正在中国多城爆发（洛阳、苏州、南京、桐乡均有媒体报道）。
  痛点原话：「从进门起就有人跟着并一直介绍，让她感觉很有压力」「不买都不好意思出门」。
  反向证据：同一批报道里，不少顾客（如 50 岁郑女士、杨女士）明确说「还是想要人详细介绍面料、给我参谋款式颜色」——说明「完全无人」牺牲了一部分人的真实需求。
- **现有解法只有两极**：
  - 完全无人（自助店 / 无人店）→ 解决「不被跟」，但牺牲「想要时被参谋」。
  - 全程导购 → 解决「被参谋」，但社恐人群压力大。
- **数字产品（GitHub）全是「AI 替你搭衣服」**：Outfitted（AI 衣橱+风格问卷）、Fit（7 题审美测验）、StyleWow（身材+肤色+场合+预算→推荐并爬电商）、FitGenie（风格 prompt→穿搭图）、FitFinder（活动穿搭生成，**纯本地、零上传、localStorage、一键复制分享**）。它们都面向「自己线上看」，没有「把需求写下来交给真人店员」这一环。
- **国内「身高体重→尺码」工具极成熟**（酷酷百宝盒、穿衣尺码小程序），但只用于网购，没有「店员当面读」场景。

→ **差异化**：在「无人」与「全程导购」之间，补一个**中间态**——把「开口问」变成「看卡帮」。保留店员帮助，但由用户定义边界。这是空白。

## 二、产品定位（一句话）

一张「购物好官卡」：你提前填好身材、风格、本次想找的、要不要导购、希望店员帮什么；到店亮给店员看，**零开口拿到精准服务**。

## 三、目标用户 & 场景

- **主用户**：社恐 / 内向 / 不想被推销，但偶尔想要专业参谋的人。
- **次用户**：语言不便（异地 / 出境旅游）、赶时间、选择困难。
- **核心场景**：线下服装店试衣前，把卡亮给店员，免去寒暄与「被跟」。

## 四、内容结构草案（字段）

| 模块 | 字段 | 用途 |
|---|---|---|
| A 基础身材 | 身高、体重、（可选）三围 / 肩宽 | 自动算 S/M/L，标注版型偏好（修身/标准/宽松） |
| B 个人标签 | 年龄、性别、（可选）体型（梨形 / 苹果等） | 辅助店员判断 |
| C 风格偏好 | 多选风格（通勤/休闲/复古/极简/甜美/辣妹/国风…）+ 喜欢色 / 雷区 | 减少无效推荐 |
| D 本次需求 | 想找品类（上衣/裤/裙/外套…）、场景（上班/约会/旅行）、预算、数量 | 出行卡核心 |
| E 沟通模式开关 | 🟢 自助模式：我自己看，需要时在卡上勾的项找您 ／ 🔵 导购模式：请按以下需求帮我推荐 | **差异化核心** |
| F 希望店员提供的帮助 | 自由文本 + 快捷选项（拿尺码 / 找试衣间 / 搭配建议 / 叫我去试 / 留货） | 把「开口」变「勾选」 |
| G 给店员的礼貌提示语 | 预置可改：「您好，我不太爱开口，但很需要您的专业眼光——请按这张卡帮我，谢谢！」 | 化解「被拒绝」感，店员不尴尬 |

## 五、交付形态对比

| 形态 | 优点 | 缺点 | 适配 |
|---|---|---|---|
| **单文件 HTML 生成器** | 零上传、localStorage 存档、手机亮屏 + 打印、与现有栈一致好维护 | 需自己开浏览器 | ★推荐 |
| 微信小程序 | 手机原生、扫码即用 | 个人开发者审核/发布成本；店员端要多一步打开 | 次选 |
| 打印 PDF 卡 | 最直观给店员 | 不便改、不存档 | 辅助 |
| 网页 + 二维码 | 生成专属链接 / 二维码给店员扫 | 需部署 | 扩展 |

**推荐**：单文件 HTML 为内核，输出「手机亮屏卡 + 一键打印」，与劳动 / 物流 tab 同栈（本地零上传、纯前端）。
