周末实战⑯：做一次数据映射（Data Mapping）与合规差距分析

第 16 周主题：数据合规 —— GDPR 与中国数据出境

数据映射就是清点家里所有钥匙：每把钥匙开哪扇门、现在在谁手里、有没有配过备份。清点完才知道哪里该换锁。
实战说明
我方（国际货代 + 德国海外仓）为跨境电商客户提供一件代发。输出一份填好的数据流清单表、角色判定、差距清单与整改优先级（P0/P1/P2）及对应合同与制度动作。
▸ 展开周末实战指令原文（可复制）
我要做一份数据映射与合规差距分析。设定：我方主体是「香港国际货代 + 其在德国注册的海外仓公司」，为一家中国跨境电商卖家（亚马逊/独立站）提供「一件代发」服务：卖家把订单推给我方 WMS，我方在德国仓拣货、打包、通过本地快递派送给欧盟买家。 请输出： 1. 一份填好的《数据流清单表》：列全数据类别 / 来源 / 字段举例 / 接收方 / 所在系统 / 法域 / 合法性基础 / 保留期（至少覆盖：买家收件人信息、卖家企业信息、卖家员工/对接人、订单与物流轨迹、清关申报个人字段、支付与退款信息、WMS 操作日志） 2. 角色判定：逐条标清我方在每条数据流里是控制者还是处理者（或共同控制者），并说明理由 3. 差距清单：对照本周学到的 GDPR（Art. 3/4/28/32/33/83 等）与 PIPL（第 38 条及豁免）要求，列出本场景缺什么（如缺 DPA、缺 SCC、保留期过长、分包处理者未披露、无 TIA、无 PIPIA、告知缺失等） 4. 整改优先级排序：P0（立即/高危）/ P1（短期）/ P2（中长期），每条给对应的「合同动作」与「制度动作」 5. 最后给一份《数据合规差距分析模板》，我之后可套用到其他客户
以下是按该指令跑出的完整内容。凡标注「待核实」处，均须以官方来源核对后方可对外使用。

一、设定复述：这票代发的「数据剖面」

我方 = 香港货代 + 德国海外仓公司，服务中国跨境电商卖家做欧盟一件代发。数据流从卖家系统 → 我方 WMS（德）→ 德国本地快递 → 欧盟买家，另有清关、支付、操作日志等支线。双法域同时触发：欧盟侧收件人/员工数据落入 GDPR（我方有德国机构，Art. 3(1) 直接适用）；中国侧卖家与买家数据出境落入 PIPL（第 38 条）。这正是本周讲的「双法域夹心」最典型场景，做映射就是先把这张网画清楚。

记忆点：一件代发的数据从「卖家订单」出发，经「我方 WMS」「本地快递」「清关」「支付」四道关卡到买家。每一道都可能是控制者或处理者，每一道都可能触发 GDPR 或 PIPL——不画清单，就不知道风险藏在哪。

三、角色判定：每条数据流我是控制者还是处理者

  • 买家收件人信息：卖家（控制者）决定收集目的，我方按订单履约存储转发 → 我方处理者；但若我方把该数据另作营销则在该目的上变控制者。
  • 卖家企业/员工信息：用于我方自身商务与 HR 对接，我方决定目的 → 我方控制者（对卖家员工数据自任控制者并须单独告知）。
  • 订单与物流轨迹：按卖家指令记录履约 → 我方处理者。
  • 清关申报字段：目的与字段由海关+卖家定，我方代填 → 我方处理者。
  • 支付信息：若我方仅转接支付机构、不决定规则 → 我方处理者；若我方自行决定扣款/退款策略则部分控制者。
  • WMS 操作日志：我方为内部管理自行决定记录 → 我方控制者（欧盟侧受 GDPR 全义务约束）。
反制点（客户/卖家视角）：卖家作为多数数据流的控制者，可要求我方（处理者）补 DPA、限定不得把收件人数据传回香港/中国总部（除非走 SCC）、不得二次利用；并可在协议中约定「我方自任控制者的 WMS 日志若泄露欧盟员工数据，由我方独立担责」。

四、差距清单：对照 GDPR 与 PIPL 找缺口

  1. 缺 DPA（Art. 28）：我方作为处理者，与卖家控制者之间未签数据处理协议 → GDPR 违法，重档罚款风险。
  2. 缺 SCC + TIA（Schrems II）：把欧盟收件人数据传回香港/中国总部，无 2021/914 SCC、无传输影响评估、无补充措施 → 非法传输，落较重档。
  3. 缺 PIPIA（PIPL）：中国侧数据出境未做个人信息保护影响评估并留痕 → PIPL 违规。
  4. 分包处理者未披露：德国本地快递、云服务商作为 sub-processor 未获卖家授权、未列名单、无责任穿透 → DPA 缺失项。
  5. 保留期过长：多处保留远超必要（如员工信息无限、企业信息 60 月）→ 违反 GDPR 第 5(1)(e) 存储限制原则。
  6. 告知缺失：未向买家告知境外接收方、出境路径、行权途径 → 违反 GDPR 第 13 条与 PIPL 告知义务。
  7. 安全措施待证（Art. 32）：传输加密、访问分级、日志审计未成体系文档 → 过程义务无证据。
⚠ 待核实 / 提示
⚠ 待核实：① 上述差距对应的具体条文项（Art. 5(1)(e)、13、28、32、33、46 与 PIPL 第 38、55 条等）以官方文本为准；② SCC 模块选择（2021/914 的 Module 适用哪一款）须核对传输双方角色；③ 香港主体在 GDPR 下视为「第三国」，传回香港同样需 SCC。

五、整改优先级 P0 / P1 / P2

优先级差距项风险合同动作制度动作
P0补 DPA（Art.28 九项）高：无协议双方违法与卖家签 DPA，含分包授权/审计/删除返还建立 DPA 模板库，接单必签
P0补 SCC+TIA（传回总部）高：非法传输重档罚在 DPA 中嵌入 SCC 2021/914 模块做 TIA 模板+补充措施（加密/假名）
P0补 PIPIA（PIPL 出境）高：PIPL 违规出境前评估并双方确认路径/豁免PIPIA 留痕 ≥3 年（须核对）

P1缩短保留期中：存储限制违规合同中写各数据保留上限WMS/系统自动到期删除策略
P1补告知（买家侧）中：透明度缺失隐私政策链接嵌入履约流程告知文案中英文双版
P2安全措施体系化低-中：过程义务证据—加密/分级/日志/渗透测试制度+SOP
P2应急与权利 SOP低-中：响应能力DPA 约定 24h 通报客户建权利响应+泄露应急 SOP 并演练
反制点（客户/卖家视角）：卖家可在 DPA 谈判中把 P0 三项设为「合同生效前提」——未签 DPA+未嵌入 SCC+未做 PIPIA 之前，卖家有权暂停推送订单数据，并主张我方违约赔偿；卖家还可要求整改时间表写入 SLA 并设违约金。

六、可套用的《数据合规差距分析模板》

  1. 第一步 画清单：按「数据类别/来源/字段/接收方/系统/法域/合法性基础/保留期」八列，逐条填。
  2. 第二步 定角色：每条标控制者/处理者/共同控制者，理由一句话。
  3. 第三步 找缺口：对照 GDPR（Art.3/4/28/32/33/83）与 PIPL（第 38 条+豁免）逐条打叉。
  4. 第四步 排优先级：P0 高危立即、P1 短期、P2 中长期，每项配合同动作+制度动作。
  5. 第五步 留证据：清单、判定、整改记录归档，作为合规自证。
实战口诀：一件代发先画数据流清单八列，再逐条定角色、找缺口、排 P0/P1/P2。P0 三件套（DPA+SCC/PIPIA）是生死线，合同动作与制度动作必须成对落地——客户能用它们反向卡我方上线，我方也能用它向监管自证已尽责。
核心术语（中英对照）
Data Mapping
数据映射 / 数据流盘点
系统梳理组织处理的所有个人数据的类别、来源、流向、系统、法域与保留期，是合规的起点
Data Inventory
数据流清单 / 数据资产清单
Data Mapping 的产物，逐条记录数据从哪来、到哪去、谁碰、留多久
Gap Analysis
差距分析
将现状与法律法规要求逐条比对，找出缺失与违规点
P0/P1/P2
整改优先级
P0 高危立即整改、P1 短期、P2 中长期；按风险与可行性排序
Sub-processor
分包处理者
代表处理者再委托处理个人数据的下游方（如本场景的德国本地快递、云服务商）
